# 探店日记 🍜

记录和小伙伴们的美食探店，多维度评分 + 云同步。纯静态网页（PWA），**零服务器、零费用**，数据存在自己的 GitHub 私人仓库里。

**线上地址**：https://xyctp0521-oss.github.io/food-log/

## 功能

- 🏆 **榜单**：按综合分 / 评价数 / 人均 / 最新排序，品类筛选 + 搜索
- ✍️ **记一笔**：选店或新建店 → 六维打分（满分 10 分）→ 菜品 + 账单 + 照片 → 标签 + 短评
- 🍽️ **菜品与账单**：逐道记菜名和价格，填总账单和人数自动算人均（还能核对菜品合计对不对得上）
- 📷 **照片**：每餐最多 9 张，上传前自动压到长边 1280 / JPEG 0.72（约 100~200KB），存成独立文件，不拖慢同步
- 👥 **多人协作**：每人一个数据文件，同时提交互不覆盖，无需注册
- 📴 **离线可用**：没信号照常记，联网自动补交（Service Worker + 本地队列）
- 📱 **像 App**：添加到主屏幕后全屏运行，有独立图标
- 💾 **备份**：一键导出/导入 JSON

## 评分维度

满分 **10 分**，六个维度**全部同向**（分越高越好），综合分取「已填维度」的平均：

| 维度 | 说明 |
|---|---|
| 味道 | 好不好吃 |
| 环境 | 装修、氛围、噪不吵 |
| 服务 | 态度、加水及不及时 |
| **价格** | **越实惠分越高**（不是越贵越高） |
| 卫生 | 桌面、餐具、后厨观感 |
| **等位** | **越快分越高**（排队时长 / 出餐速度） |

可以只填其中几项，综合分只按填了的算 —— 赶时间就打个味道也能记。

## 第一次使用（建数据仓库 + 令牌，约 3 分钟）

### 1. 建数据仓库

新建一个**私有**空仓库，名字 `food-log-data`，不要勾任何初始化选项：

https://github.com/new?name=food-log-data&visibility=private

### 2. 生成 Fine-grained Token（精确授权，比 classic 安全）

打开 https://github.com/settings/personal-access-tokens/new

| 字段 | 填什么 |
|---|---|
| Token name | `food-log` |
| Expiration | 90 days（到期重新生成） |
| Repository access | **Only select repositories** → 只选 `food-log-data` |
| Permissions → Contents | **Read and write** |
| Permissions → Metadata | Read-only（自动勾上，必需） |

生成后复制 `github_pat_...` 开头的令牌（只显示一次）。

> 为什么不建议用 classic token：classic 勾 `repo` 等于你**所有**仓库的读写权，泄露了很麻烦。Fine-grained 只能碰这一个仓库。

### 3. 在网页里配置

打开站点 → 设置页：

- 昵称：你自己叫啥
- GitHub 用户名：`xyctp0521-oss`
- 仓库名：`food-log-data`
- Personal access token：上面复制的
- 分支：`main`

点「测试连接」，看到 ✅ 再保存。首次提交后仓库会自动生成：

```
data/
├── places.json          # 所有店铺（公共）
├── photos/
│   └── ph_xxxxxxx.jpg   # 照片（每张一个独立文件，JSON 里只存 id）
└── users/
    └── u_xxxxxxxx.json  # 每人一个文件（昵称哈希命名）
```

照片单独存的好处：同步时只拉几十 KB 的 JSON，图片点开才下载，不会因为图片多就卡死。

## 关于内置的同步配置（安全说明，请读完）

代码里存的是**用登录密码加密过的配置密文**（AES-GCM），不是明文。两个原因：

1. 公开仓库里的明文 GitHub token 会被 GitHub secret scanning 扫到并**自动吊销**，功能直接失效
2. 加密后，随便翻代码的人拿不到能用的 token

**但要说清楚：真实保护强度 = 密码强度。** 初始密码是 8 位纯数字，理论上可离线爆破。所以这套设计的定位是「防路人和防误操作」，不是防定向攻击。

真正的隔离靠这三层：

- token 只授权**一个**私有数据仓库，且只给 Contents 权限（碰不了你其它项目）
- 数据仓库是私有的，代码仓库里没有任何真实数据
- token 一旦觉得不对，随时去 GitHub 吊销重发（吊销后只需重新生成密文并推一次代码）

想提高强度：换一个长的独立密码重新生成密文，或者退回「每人手动填配置」。

## 注意事项

- **GitHub API 在国内会抖动**（实测直连 0.2s ~ 1.3s 波动）。应用已做离线优先 + 自动重试：同步失败不丢数据，只是延迟，下次打开自动补交
- 认证后限流 **5000 次/小时**，正常使用远够不上
- 令牌存在各人自己浏览器的 localStorage 里；换设备要重新填
- 「修改评分」写同一份用户文件，GitHub 端带 sha 冲突重试，正常用不会丢数据

